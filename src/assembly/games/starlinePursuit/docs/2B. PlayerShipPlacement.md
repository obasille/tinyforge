Below is a complete description of **player start state and ship placement structure**, designed to:

* Prevent trivial blocking
* Encourage early scanning decisions
* Make deployment meaningful
* Preserve the chase dynamic

All assumptions:

* 320×240 map
* ~25–35 stars
* Lanes pre-generated
* Target already spawned but hidden

---

# 1. Player Starting Position Philosophy

The player does **not** start distributed across the map.

They start:

* Centralized
* Under-informed
* Resource-limited
* Deployment-constrained

This forces:

* Early information gathering
* Strategic branching
* Commitment tradeoffs

---

# 2. Starting Location Model

## Primary Option (Recommended)

### Single Command Base Star

Player begins with:

* 1 Command Star (home system)
* All ships docked there

Location:

* Near map center
* Slightly offset (not perfectly central)
* Not directly adjacent to rim exits
* Not inside nebula

Why:

* Ensures equal distance to most clusters
* Prevents immediate exit blocking
* Keeps early game focused on deployment

---

## Alternative (Advanced Mode)

### Dual Forward Outposts

Player begins with:

* 1 Central Base
* 1 Light Outpost (pre-deployed sensor platform)

Outpost is:

* 3–5 jumps away
* Located near mid-density region

Purpose:

* Gives slight directional bias
* Speeds up early branching

---

# 3. Starting Ship Inventory

Example baseline loadout:

| Unit         | Quantity | Role             |
| ------------ | -------- | ---------------- |
| Scout Ship   | 2        | Fast scanning    |
| Interceptor  | 1        | Capture          |
| Sensor Buoy  | 2        | Static detection |
| Deep Scanner | 1        | High-cost sweep  |

No ship begins deployed except at base.

---

# 4. Initial Information State

At game start:

* Target location unknown
* No systems scanned
* No trail visible
* Target has already moved 1–2 turns (hidden head start)

This prevents immediate optimal path prediction.

---

# 5. Deployment Mechanics at Start

## Ships at Base

Ships must:

* Spend 1 turn to launch
* Then move along star lanes normally

This creates an initial tempo choice:

Turn 1:

* Launch multiple ships?
* Or configure scanner first?

---

## Sensor Buoys

* Must be transported by Scout or Interceptor.
* Cannot be placed instantly.
* Deployment consumes a turn.

This prevents instant global coverage.

---

# 6. Early Game Decision Pressure

On turn 1–3, player must choose:

### Option A — Wide Scan

* Send scouts in opposite directions.
* Risk thin coverage.

### Option B — Cluster Focus

* Send both scouts toward nearest cluster.
* Risk target elsewhere.

### Option C — Defensive Net

* Deploy buoys near center.
* Slow expansion.

Because:

* Resource costs apply
* Movement time matters
* Target already moving

There is no “correct” default opening.

---

# 7. Preventing Early Blocking

To avoid trivial exit camping:

1. Exits are at least 4–5 jumps from base.
2. Multiple exit candidates exist.
3. Some targets do not use exits.
4. Some exits may not be active for that target.

This ensures:

* Player cannot pre-block blindly.
* Must gather intelligence first.

---

# 8. Optional Advanced Opening Variants

## A. Delayed Interceptor Activation

Interceptor:

* Locked for first 2 turns.
* Represents mobilization time.

Forces scouting-first gameplay.

---

## B. Fog-of-War Sensors

Player initially sees:

* Only star positions and lanes.
* No system properties until scanned.

Makes early direction selection uncertain.

---

## C. Asymmetric Map Start

Base is not centered but slightly biased.

Creates:

* Different early expansion geometry
* Replay variety

---

# 9. Why Centralized Start Is Important

If player begins:

* Pre-distributed → early net too strong
* On edge → trivial escape blocking
* Near nebula → Ghost target too weak
* Near cluster → Pirate too easy to defend

Centralized but slightly imperfect position ensures:

* Equal access to clusters
* Meaningful branching
* No immediate dominance

---

# 10. Typical Turn 1 Flow

1. Target already at unknown system.
2. Player launches:

   * 2 Scouts in diverging directions.
3. Decides whether to:

   * Hold interceptor
   * Or commit early toward a predicted region.
4. No detection yet.
5. Chase tension begins immediately.

---

# Summary

Player starts:

* With all ships docked at a single central command star.
* With limited initial resources.
* With no intel.
* With target already in motion.

Ship placement is centralized and delayed, forcing:

* Information-first gameplay
* Strategic branching
* Resource tradeoffs
* No trivial exit blocking
