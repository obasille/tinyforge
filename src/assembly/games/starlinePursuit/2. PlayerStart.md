## 1. Where do the player ships start from?

Player ship starting positions are a major part of the strategy and difficulty. There are several good structures; the best fit is usually a combination.

---

### A. Single Home Base (Standard Start)

All player ships begin at one system: **Command HQ**.

- Usually near the center of the map
- Represents the fleet’s staging point

Pros:

- Clear and readable
- Player must expand coverage outward
- Early turns are about choosing directions

Cons:

- Can feel slow if the target starts far away

Best for:

- Beginner missions

---

### B. Split Deployment Start (More Tactical)

Ships start at different predefined locations:

- Survey Cruiser at HQ
- Scout already forward-deployed
- Beacon Tender near a chokepoint

Pros:

- Faster early decisions
- Encourages specialization immediately

Cons:

- Slightly more complexity

Best for:

- Medium difficulty

---

### C. Player Chooses Starting Systems (High Agency)

Before turn 1, the player places ships in a limited zone:

- “Deploy up to 2 ships within 2 jumps of HQ”

Pros:

- Strategic planning from the start
- Replayability

Cons:

- Can allow optimal setups if unrestricted

Best for:

- Advanced mode

---

### D. Dynamic Start Based on Initial Intel (Narrative)

The player starts near the last known sighting:

- “Target was seen near Sector B”

Ships spawn in that region.

Pros:

- Feels realistic
- Avoids slow openings

Cons:

- Reduces mystery if too precise

Best for:

- Story missions

---

### Recommended Approach

Use:

- **HQ start for Interceptor + Survey**
- **Scout starts 2–3 jumps forward**
- **Beacon Tender starts near a major hub**

This creates immediate meaningful choices without full freedom.

## 2. If target goals are constrained, isn’t it too easy to block or camp?

Yes, if the target is simply:

- “Reach one of 2 escape nodes”
- “Go to the nebula”

Then the player can camp those endpoints.

To keep the chase strategic, the target’s objective must not collapse into a single obvious destination.

The solution is to design the target around **routes, uncertainty, and timing**, not fixed endpoints.

Below are the key methods.

---

# A. The Target Goal is Known, but the Route is Not

Even if the player knows the target wants to escape, the question is:

**Which corridor will it take?**

A good map has:

- 3–5 viable paths
- multiple chokepoints
- tradeoff routes (fast but risky, slow but hidden)

Camping one exit is not enough.

---

# B. Multiple Possible Escape Points (Not 1–2)

Instead of 2 escape systems, use:

- 4–6 possible exits

Only 1 is real, or the target chooses dynamically.

Player cannot cover all.

---

# C. Target Can Change Goal Mid-Run

Target behavior adapts:

- If Exit A is heavily scanned → reroute to Exit C
- If cornered → dive into nebula instead

This prevents static solutions.

---

# D. Player Blockades Are Temporary and Costly

Blocking should never be “place and forget.”

Blockade characteristics:

- lasts 1–2 turns
- consumes major resources
- requires a ship to remain stationed

So the player must time it correctly.

---

# E. The Player Does Not Know the Goal Initially

The target type is unknown at first.

Early game is about answering:

- Is it escaping?
- Is it heading to a hub?
- Is it hiding?

Only later does the player identify behavior.

This preserves mystery.

---

# F. The Target Uses Deception

Targets can:

- drop false trails
- trigger fake signals
- briefly go dark in nebula zones

So camping the “goal” is insufficient without confirmation.

---

# G. The Target Is Not Trying to Reach a Place, But to Avoid Capture

The strongest model:

**The target’s objective is survival.**

It has no fixed destination.

It simply:

- avoids scanned zones
- avoids the interceptor
- keeps moving

This creates an emergent chase with no endpoint camping.

Escape occurs only if it survives long enough.

---

# H. Time-to-Intercept Matters More Than Destination

Even if you know the target will pass through Hub X eventually:

- Can you get there in time?
- Can you position the Interceptor correctly?

The game is about timing and travel constraints, not location alone.

---

# I. Moving Windows, Not Static Goals

Instead of “reach nebula,” use:

- “Meet contact at hub between turns 12–15”
- “Escape window opens at turn 20”

Player must intercept in the correct time window.

Camping too early wastes resources.

---

## Best Practice Recommendation

Use this combination:

- Target has 4–6 possible exits
- Target adapts route if scanned
- Goal is not revealed immediately
- Blockades are short and expensive
- Some targets have no destination, only evasion

This ensures the game remains about:

- prediction
- sensor net building
- timing
- commitment under uncertainty

Not about camping the obvious endpoint.
